# 开发者迁移

本次是明确的公共边界切换，不保留旧内部包的转发类、别名注册器或晚注册通道。目标仍是 Minecraft 1.20.1 / Forge 47.3.0；没有声称兼容其他加载器或 Minecraft 版本。

## 从内部类迁移

| 旧接入方式 | 当前方式 |
| --- | --- |
| 修改或调用内部菜单注册表 | 在 `SaoUiRegisterEvent` 中调用 `registry.menu(...)` |
| 导入 `client.menu` 中的面板、条目、上下文类型 | 导入 `api.menu` 中的同职责契约 |
| 字符串面板 ID、裸纹理短名 | 自有命名空间的 `ResourceLocation` |
| 根据字符串格式猜测翻译键 | 显式 `Component.translatable` 或 `Component.literal` |
| 在 HUD 渲染末尾另插一条固定调用 | 注册 `HudElement`，选择绘制 pass、可见性和布局绑定 |
| 给核心设置枚举、开关表添加分支 | 注册自有 `SettingsGroup` 和类型化设置项 |
| 附属模组写入核心 `saomenu.json` | 由附属模组自己提供保存、复位回调和配置文件 |
| 直接依赖内部 `ThemeColors` | 使用 `api.theme` 的颜色、字体、运动令牌 |
| 在世界事件中绕过组合层绘制 | 注册 `WorldOverlay`；对应当前 `AFTER_ENTITIES` 阶段 |
| 将实体或世界引用一直存在静态字段中 | 使用 `SessionListener` 处理世界身份变化；绘制时读取当前上下文 |
| 手写输入缓冲或反射寻找弹层方法 | 使用原生字段及 `SaoScreen`、`SaoScrollPane`、`SaoConfirmDialog` |

## 时机与失败行为

只在客户端 Forge 注册事件内同步提交贡献。跨线程、事件返回后的修改及同领域重复 ID 都是错误。不要通过捕获这些异常来伪装注册成功，也不要轮询一个可变注册表等待条目出现。

内置贡献先注册，随后统一按 `order` 和完整 ID 排序。不要保存一个可见槽位下标作为长期身份；动态列表重排后应仍以条目 ID 定位。动态菜单列表的缓存和失效由贡献方负责。

`SaoUi.selectTheme` 对未知 ID 抛出异常；其作用是选择内存主题，不擅自保存其他设置。旧用户配置和旧主题 JSON 的短 ID 在加载边界迁移为 `saomenu:<id>`，保存后使用完整 ID；运行时没有裸名主题别名。

## 屏幕生命周期

- `SaoScreen.buildContent` 在每次挂载时创建控件；`layoutWidgets` 在尺寸变化时移动现有控件。
- `disposeMount` 对应一次卸载，不能把它误当作对象永久销毁。需要保留的草稿应由屏幕模型持有。
- `SaoConfirmDialog.open` 使用 Forge 原生 GUI 层。父屏幕不因弹出确认框而卸载；取消不调用确认动作，确认成功弹层返回后才执行动作。
- 公开字段控件保持原生 `EditBox` 语义；不要同时让全局快捷键消费正在编辑的普通字母。
- HUD 绘制上下文是借用对象，不能保存到下一帧。编辑器检查可见性时 `graphics()` 为 `null`，可见性判断不得调用绘制。
- 世界姿态栈的外层隔离不免除回调平衡内部 push/pop、缓冲和渲染状态的责任。

## 验证自己的附属模组

使用发行 JAR 作为 `modImplementation` 二进制依赖，而不是把核心源码拷进项目。独立示例演示全部当前注册领域及独立配置持久化，见 [快速开始](quickstart.md)。至少检查：注册冻结、长列表、GUI 缩放、弹层取消、断开/重连，以及自身客户端类不会从服务端入口加载。

开发预览、旧的本地物品栏夹具和内部 `debug*` 方法都不属于公共 API。客户端截图也不证明服务端已接受真实物品操作。
